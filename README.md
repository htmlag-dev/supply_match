# Supply Match

Приложение для покупок и закупок B2B, B2C и C2C: поиск продавцов, личная база, каталоги, корзина, сравнение полной стоимости и ведение заказов. Один интерфейс используется в браузере, PWA и проектах Android/iOS.

## Быстрый запуск

Нужен Python 3.11+ с поддержкой SQLite serialize/deserialize. Рекомендуется отдельное окружение:

```sh
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python main.py --no-ai-download
```

Windows: активируйте `.venv\Scripts\activate`. Приложение открывается на http://localhost:8000. Вход обязателен; для регистрации и восстановления пароля нужен SMTP. Создание первого администратора:

```sh
python scripts/admin.py create --email owner@example.com
```

Пароль вводится скрыто. Подробности: [аккаунты и безопасность](docs/SECURITY_AND_ACCOUNTS.md). `.env.example` перечисляет переменные среды; файл `.env` автоматически не читается.

## Возможности

- Поиск по товару, региону и формату сделки. Веб-поиск через DDGS; дополнительные подключения Tavily и Gemini. Источники не гарантируют актуальность цены и наличия.
- Локальная Qwen3 через llama.cpp или собственные API-ключи OpenRouter, Groq, Gemini, Anthropic и совместимого сервера. Локальная автоустановка пока поддерживает Windows x64. На других системах нужен настроенный совместимый сервер или облачный провайдер.
- Личные базы поставщиков с контактами, статусами, заметками и CSV-экспортом.
- Каталоги моделей: артикул, цена, валюта, наличие, минимальная партия, сроки, ссылка на источник и дата ручной проверки. Непроверенные и проверенные более семи суток назад условия отмечаются как требующие проверки.
- Импорт CSV/XLSX: предпросмотр всех строк, проверка до записи, обновление по артикулу `sku`. XLSX: первый лист без формул. При изменении файла или каталога предпросмотр нужно повторить.
- Смешанная корзина и сравнение идентичных моделей по полной стоимости. Учитываются введённые расходы, курсы, минимальная партия, остатки и сроки. Неизвестные расходы не считаются нулевыми.
- Заказы: отдельные этапы согласования, ожидания оплаты, отправки, получения и завершения; трек-номер, перевозчик, комментарии и история. Факт онлайн-оплаты подтверждает только провайдер.
- Закупочные проекты с бюджетом, заметками и связями с поставщиками, моделями и заказами. Остаток бюджета рассчитывается в валюте проекта; заказы в других валютах показываются отдельно. Проекты личные; совместная работа команды пока не реализована.
- Сохранённые поиски, ежедневная проверка по явному включению и уведомления внутри приложения о новых ссылках. Также уведомления об изменении цены/наличия при редактировании или импорте каталога. Автоматического извлечения цен из произвольных сайтов нет.
- Почтовое восстановление пароля с одноразовым кодом и отзывом всех сессий; регистрация с подтверждением email, роли и админ-панель.
- Зашифрованные резервные копии SQLite, проверка целостности и восстановление в новую папку. Опциональное серверное хранилище PostgreSQL с инструментом переноса данных.
- Темы оформления, настройка контраста, PWA-оболочка и мобильные проекты Capacitor.

## Тарифы и оплата

| План | Цена | Поставщики | AI-действия | История |
|---|---|---:|---:|---|
| Пробный | 14 дней бесплатно | 100 | 50 за пробный период | Да |
| Старт | Бесплатно | 20 | 5 в календарный месяц UTC | Нет |
| Профи | 990 ₽/месяц или 9 900 ₽/год | 1 000 | 300 в календарный месяц UTC | Да |
| Команда | Будущий план | Не реализовано | Не реализовано | Не реализовано |

Проверка сохранённого поиска расходует одно AI-действие. Ошибки поиска возвращают действие. Личные внешние API оплачиваются отдельно. Подписка приложения и оплата товара — разные операции. Для оплаты нужны подключённые реквизиты; без них создаётся заказ без списания. Возвраты, escrow и автоматическое взаимодействие с перевозчиками не реализованы. См. [платежи](docs/PAYMENTS.md).

## Размещение и резервные копии

По умолчанию используются личные зашифрованные SQLite-файлы и один серверный процесс. Для удалённого доступа нужны HTTPS reverse proxy и переменные production из инструкции безопасности. Для PostgreSQL установите `requirements-server.txt` и используйте [инструкцию переноса](docs/OPERATIONS.md). Хранилище существующей установки автоматически не переключается.

```sh
# Остановите сервер. Ключ шифрования хранится отдельно от архива.
python scripts/backup.py create backups/supply-match.smb
python scripts/backup.py verify backups/supply-match.smb
python scripts/backup.py restore backups/supply-match.smb --destination restored-data
```

SMTP, OAuth, платёжные аккаунты и публичный сервер требуют реквизитов владельца. Скрипт резервирования SQLite не предназначен для PostgreSQL; там используйте pg_dump/pg_restore и шифрование резервных копий.

```sh
python -m unittest -q
node --test tests/theme.test.cjs
# Проверить все JS-файлы
for file in app/web/*.js; do node --check "$file"; done
```

GitHub Actions выполняет проверки SQLite/PostgreSQL и сборку Android debug APK. Это не проверка мобильных приложений на реальных устройствах. Локально на текущем Mac Xcode и Android SDK отсутствуют; APK/IPA не подтверждены как собранные.
