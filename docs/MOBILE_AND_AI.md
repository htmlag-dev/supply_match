# Сайт, Android, iOS и встроенный ИИ

## Что подготовлено

- `app/web/` — адаптивный сайт и PWA с manifest, иконками и offline-оболочкой.
- `mobile/android/` — проект Android Studio на Capacitor 8.5.3.
- `mobile/ios/` — проект Xcode с Swift Package Manager.
- `mobile/capacitor.config.json` — app ID `com.supplymatch.app`, имя Supply Match; перед выпуском замените ID на свой уникальный.
- `scripts/prepare-mobile.mjs` — копирование интерфейса, настройка API URL и сборка native bridge.

Проекты платформ **сгенерированы и синхронизированы**, но APK/IPA не собраны, не подписаны и не опубликованы. На текущем Windows-компьютере нет Android SDK/JDK 21; iOS-сборка требует Mac и Xcode. Исполнение на реальном телефоне/эмуляторе не проверялось.

## Установка как PWA

После размещения сайта по HTTPS откройте его на устройстве:

- iOS: Safari → Поделиться → На экран «Домой».
- Android: меню браузера → Установить приложение / Добавить на главный экран.

На компьютере localhost также подходит для PWA. LAN HTTP-адрес не даёт всех возможностей service worker. Без сети оболочка может открыться, но API, личная база, поиск и платежи требуют работающего сервера. Данные из API и ключи не попадают в offline-кэш.

## Подготовка native-ресурсов

Нужен Node.js 22+ и pnpm.

```powershell
pnpm install --ignore-scripts
# Необязательно: вшить адрес своего HTTPS API в сборку (секреты вшивать нельзя)
$env:SUPPLY_MATCH_MOBILE_API_URL = 'https://ваш-домен'
pnpm mobile:sync
pnpm mobile:android
```

На Mac:

```sh
pnpm mobile:ios
```

Если адрес не задан при сборке, после первого запуска укажите его на экране «Подключение к серверу». Этот URL сохраняется на устройстве, токен доступа хранится в sessionStorage на время сессии. Для публичного продукта обычно заранее задают HTTPS-домен сервера и реализуют пользовательскую авторизацию.

В Android Studio нужны SDK 36, build tools и JDK 21; для iOS — Xcode, выбранная команда подписи и аккаунт разработчика. Сборка и публикация выполняются в соответствующих IDE. Не включайте `data/`, SQLite, веса Qwen или секреты платёжных систем в мобильный пакет.

## Сервер для мобильных клиентов

Python остаётся на компьютере/сервере. Qwen также выполняется **на сервере**, а не на iPhone или Android. Встроенный режим не означает, что каждый телефон загружает 2,4 ГБ весов.

Для удалённого доступа используйте HTTPS reverse proxy перед Python-сервером. Передавайте правильный Host и настройте среду процесса:

```text
SUPPLY_MATCH_PUBLIC_HOST=ваш-домен
SUPPLY_MATCH_TOKEN=<длинный случайный токен пространства>
SUPPLY_MATCH_ALLOWED_ORIGINS=capacitor://localhost,https://localhost
```

Токен вводится в мобильном экране подключения и передаётся как Bearer Authorization. CORS разрешается только перечисленным origins. Без переменной `SUPPLY_MATCH_TOKEN` это локальный режим без авторизации; он не подходит для публикации личной базы в интернете.

Сейчас токен открывает **одно рабочее пространство**. Независимые пользовательские аккаунты и изоляция данных между клиентами не реализованы. Для публичного SaaS нужны accounts/workspaces, ограничение запросов, резервное копирование и отдельное хранение секретов пользователей; текущий локальный SQLite API не следует выдавать за готовый массовый сервис.

## AI по умолчанию

После `python main.py` установленная модель стартует автоматически. На чистой Windows x64 модель загружается при первом запуске в фоне. Статус загрузки виден в приложении. Отключить автоматическую загрузку можно флагом `--no-ai-download`.

Выбрана официальная **Qwen3-4B Q4_K_M** через CPU llama.cpp. Модель проверена реальным запросом на этом компьютере. Ориентировочное потребление: несколько ГБ RAM и около 2,4 ГБ на диске; скорость зависит от CPU. Это локальный бесплатный вариант, а не обещание качества крупнейших облачных моделей.

Runtime слушает только 127.0.0.1:8766 и защищён случайным ключом, переданным процессу через окружение. Ключ не вшивается в приложения и не выводится в API.

Fallback встроенного режима — OpenRouter `openrouter/free`, если владелец сервера настроил `SUPPLY_MATCH_OPENROUTER_KEY`. Это по-прежнему требует служебного аккаунта провайдера; алгоритм не создаёт чужие аккаунты/ключи и не переходит на платные модели.

Живые веб-результаты требуют Tavily или Gemini. Без них модель предлагает только непроверенных кандидатов и не публикует придуманные цены/контакты. Источники веб-поиска отображаются отдельно.

## Оплата на мобильных устройствах

Заказы физических товаров используют подключение выбранного продавца и защищённую страницу провайдера в native Browser plugin. Подписка на цифровые функции приложения требует отдельного подключения store billing перед выпуском; сейчас native-клиент может оставить заявку на тариф. Реальные платежи и возвраты нужно проверить в тестовом магазине до публикации.
